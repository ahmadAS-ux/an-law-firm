Existing rows (defaulted to `isDemo: false`) are protected; never infer disposability from names.

## Phase 5 — Auth hardening (staging boundary now, SSO later)
1. **Token (Edge-compatible):** payload `{uid, exp, iat}` → base64url; `HMAC-SHA256(payload, NEXTAUTH_SECRET)`; cookie = `payload.signature`. Implement in `src/lib/session-token.ts` using **Web Crypto only** (`crypto.subtle.importKey` + `crypto.subtle.sign`/`verify`) with **no Node `crypto`, no Prisma, no `server-only` import**, so Next.js 14 middleware (Edge runtime) can call it. Signature comparison: use `crypto.subtle.verify` (constant-time inside the platform) or a manual XOR loop over equal-length byte arrays — never `===` on strings. Malformed → null; `exp` = now + 12h checked on every request. Fail closed: secret missing or < 32 bytes → verifier returns null, login 503 with logged error. `src/lib/auth.ts` (Node runtime) reuses the same verifier and then performs the **database** checks (`isActive`, `deletedAt`) — middleware verifies the token only; handlers verify the user.
2. **Picker off by default:** server-only `DEV_LOGIN_PICKER_ENABLED === "true"`. Off → user-list and picker login 404. On → login also requires `DEV_LOGIN_SECRET` in the request body (constant-time compare; wrong/missing → 401 after 1s delay).
3. **Login UI updated to match:** the login page gets a localized password field (`auth.devSecret` in `ar.ts`/`en.ts`, with `<bdi dir="ltr">` around any Latin fragment); `AuthProvider.login(userId, devSecret)` sends it once, never stores it, never reads it from any `NEXT_PUBLIC_*` variable. When the picker is disabled the page shows a localized "login unavailable — contact administrator" state instead of an empty list.
4. **Shared staging boundary:** HTTP Basic auth when `STAGING_BASIC_AUTH="user:pass"` is set, applied by middleware to every path including dotted assets and `/api/*`.
5. **Middleware order (explicit, implemented in this order, matcher covers dotted paths):**
   1. Legacy `/uploads/**` → 404 unconditionally (before anything else).
   2. `STAGING_BASIC_AUTH` check → 401 with `WWW-Authenticate: Basic` if missing/wrong.
   3. `/api/auth/users` and `/api/auth/login` → picker rules (404 when disabled).
   4. **Public allow-list (after Basic auth, no app session required):** `/login`, `/api/auth/login`, `/api/auth/users`, `/api/auth/me` (returns 401 JSON itself when no session), `/_next/*`, `/favicon.ico`, `/logo.png`, `/fonts/*`, `/images/*`, `/api/uploads-denied`. Everything the login page needs must be on this list — test that `/login` renders with Basic credentials and no session.
   5. Other `/api/*` without a valid token → JSON 401 (token check only, Edge-safe).
   6. Protected pages without a valid token → redirect to `/login`. Handlers still call `getCurrentUser()` for inactive/deleted checks; a valid token for a deactivated user passes middleware and is rejected by the handler.
6. **Types:** server-side `SessionUser` (`id, roleId, dbRole.name, departmentId, teamId, isActive, deletedAt, role`) from `getCurrentUser()`; `ClientUserDTO` (`id, name, nameAr, email, roleName, departmentId, teamId, avatarUrl, role`) via one `toClientUser()` used by both login response and `/api/auth/me`. `getCurrentUser()` → null when inactive or soft-deleted.
7. Cookie flags: `httpOnly`, `sameSite: "lax"`, `secure` in production, `path: "/"`, `maxAge` 12h. Users re-login once.
8. Tests (state per test whether valid Basic credentials are supplied — with `STAGING_BASIC_AUTH` set, every HTTP test supplies them unless the test is specifically about Basic auth): valid → user; tampered payload/signature → null; expired → null; malformed → null; missing secret → null + login 503; inactive/soft-deleted → null; picker disabled → 404; picker enabled without dev secret → 401; direct login POST with arbitrary uid → 401; `/api/*` unauthenticated → 401 JSON; Basic auth missing on a dotted asset and on `/api/tasks` → 401; Basic auth present, session absent, page → redirect; `/login` and `/_next/static/*` load with Basic auth and no session; valid token for a deactivated user → middleware passes, handler 401.

## Phase 6 — Private uploads
1. **Storage contract:** `File.storageKey` key format `<yyyy>/<mm>/<cuid>.<ext>`, server-generated. New records always set `storageKey`; `url` (now nullable) is never written. Root `UPLOAD_DIR ?? .uploads` (gitignored). Resolve with `path.resolve(root, key)`; reject if outside root, absolute, or containing `..`, `\`, leading `/`.
2. **Two policies, not one:**
   - `canReadFile(user, file)` — list, detail, download. `manageFiles` → yes; file with `caseId` → the exact rule `/api/files` GET uses today (Employee = assignee access); `matterId`/`clientId`/`invoiceId` without case, or no parent → `manageFiles` only (interim; v0.8.0 refines).
   - `canDeleteFile(user, file)` — preserves today's `manageFiles` requirement. Never derived from read access.
   - Upload keeps its existing authorization.
   Storage resolution is shared; authority is not.
3. **Download** `GET /api/files/[id]/download`: session → else 401 JSON; row (not soft-deleted) → else 404; `canReadFile` → else 404; stream from `storageKey`, or read-only fallback from legacy `url` under `public/uploads` for un-migrated rows (logged); headers `Content-Type`, `Content-Disposition: attachment; filename*=UTF-8''…`, `Cache-Control: private, no-store`; `AuditLog{action:"FILE_DOWNLOAD"}`.
4. Update upload, list, detail, DELETE (resolve via storage contract; soft-delete; physical purge only via a future `PURGE_FILES=yes` script).
5. UI: all file links → download route; remove `/uploads/` URL construction.
6. **Legacy URL denial (effective, not decorative):** (a) middleware rule 5.5.1 with a matcher that includes dotted paths; (b) `next.config.mjs`:
```js
async rewrites() {
  return {
    beforeFiles: [{ source: "/uploads/:path*", destination: "/api/uploads-denied" }],
  };
}
```
with `src/app/api/uploads-denied/route.ts` returning 404 for all methods — `beforeFiles` runs before public-file lookup, an ordinary rewrite does not. **Test with a real file** placed at `public/uploads/test-deny.pdf` in the integration environment: `GET /uploads/test-deny.pdf` → 404 both without a session and with a valid session + Basic credentials. The migration copies files and retains sources; `public/uploads` is not assumed empty.
7. **Recoverable migration** `scripts/migrate-uploads.ts` (not run here): `--dry-run` inventory (source exists / missing / collision); real run copies, SHA-256 both sides, then `UPDATE File SET storageKey`; progress log `scripts/migrate-uploads.progress.jsonl` (**gitignored**) is a hint only — a row is skipped only if the DB already has `storageKey` **and** the destination file's checksum matches; otherwise it is reprocessed. Sources never deleted by the script; `--verify` re-hashes; recovery = restore dump, rerun.
8. `AZURE.md`: v1.0 requires Azure Blob behind the same route; staging persistence to be verified, not assumed.
9. Tests: unauthenticated → 401 JSON; no access → 404; authorised → 200 + attachment headers; traversal/absolute keys rejected; real legacy file → 404; Employee on unassigned case: list hides and download 404 agree; Employee assigned to case: read 200, DELETE 403.
